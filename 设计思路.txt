RAG系统设计思路
================================================================================

向量模型：bge-large-zh-v1.5（1024维，BAAI）
重排序模型：bge-reranker-v2-m3（BAAI FlagEmbedding，sigmoid归一化）
向量库：ChromaDB（PersistentClient，本地HNSW索引）
翻译API：DeepSeek（deepseek-v4-flash）
答案生成：DeepSeek（deepseek-v4-flash，基于检索文档+上下文扩展）
关键词检索：BM25Okapi（rank_bm25）+ jieba分词
出题/评分：DeepSeek + BGE-reranker 混合流水线

================================================================================
1. 全量更新（_rebuild_index_inline 实现）
================================================================================

流程：
  a. 清空旧 chroma_db，新建集合 sillytavern_docs
  b. 读取 RAG/SillyTavern-Docs/ 下所有 .md 英文文档（排除 _includes/.github/node_modules/static）
  c. 加载翻译缓存 RAG/translation_cache.json：
     - 缓存的 key 是英文原文的 MD5 hash
     - 缓存文件顶层包含 __commit__（SillyTavern-Docs 的 git commit id）和 translations（翻译映射表）
     - 如果 __commit__ 与当前 git HEAD 不一致，弃用全部旧缓存，从零翻译
     - 如果一致，命中缓存的文档直接使用，未命中的调用 DeepSeek API 翻译
  d. 翻译：每完成一篇立即写回缓存（含 commit id），确保中断后可续传
  e. 切片（两级策略）：
     - 第一级：按 ### 标题切分原始文档
     - 第二级：如果某段 >2000 字符，按空行（段落）二次切分，每段 ≤1800 字符
     - 每个chunk记录 chunk_index（在源文件中的序号）和 source_file（源文件路径），供上下文扩展使用
  f. 向量化：BGE-large-zh-v1.5 批量编码，写入 ChromaDB
  g. 附加正则知识库：
     - RAG/README.md → 按 ## 标题切分，标注为 learn-regex（表层语法）
     - RAG/正则表达式/rag_chunks/*.txt → 标注为 mastering-regex（中层原理）
  h. QA预补全：在题库中每题的答案+关键点拼成QA风格文档，标注 type=qa_presupplement
  i. 构建 BM25 索引（含 hash→metadata 映射表），供混合检索使用

================================================================================
2. 增量更新（TODO）
================================================================================

计划流程：
  a. git fetch/pull 获取最新 SillyTavern-Docs
  b. 对比 commit id，如果与缓存中的 __commit__ 一致则跳过
  c. 识别新增/修改的 .md 文件，只翻译变化部分
  d. 删除旧版对应 chunk（通过 source 元数据筛选），保留 supplement 和 qa_presupplement
  e. 新chunk切片→向量化→入库，更新 BM25 索引

================================================================================
3. 向量主次关系（metadata分层）
================================================================================

优先级从低到高：
  第0层：translated_official_docs（SillyTavern官方文档中文翻译）— 最底层
  第1层：mastering-regex（《精通正则表达式》切片）— 权威资料
  第2层：learn-regex（README.md 正则语法）— 表层知识
  第3层：qa_presupplement（QA预补全，type=qa_presupplement）— 基于题库生成的补充
  第4层：supplement（循环优化过程中生成的补充块）— 最高层

补充块去重机制：
  - KnowledgeWriter 在写入前查询 ChromaDB，检查是否已有相同来源+相同关键点的补充块
  - 避免重复嵌入相同内容

================================================================================
4. 知识域分类
================================================================================

题目按5个知识域自动分类（classify_question_module 实现，基于问题+答案+关键点全文匹配）：

  regex          — 正则表达式 / Regex脚本 / 替换模式
  worldinfo      — 世界书 / World Info / 递归扫描 / 激活策略
  macros         — 宏 / Macros / 变量 / 动态输出
  stscript       — STscript / 快捷指令 / slash命令
  general        — 跨域综合应用 / 管道协作

================================================================================
5. 循环测试（循环测试.py 主入口 run_orchestrator）
================================================================================

目标：
  对Silly Tavern知识库进行"测试 → 评分 → 分析 → 补充 → 更新 → 复测"闭环优化
  达标标准：均分≥9.0 且 无单题<7.0

出题策略（v7 模块聚焦版）：
  - 第1轮：全面摸底，从5个知识域各抽2题（共10题），识别最薄弱模块
  - 第2-5轮：聚焦最弱模块，全部10题只出该模块；每轮主动用LLM生成3道新题入库
  - 某个模块题库耗尽或用完 → 标记为"已修复"，切换下一最弱模块

子智能体（全部实现在 orchestrator 内部）：

  ┌─────────────────────────────────────────────────────────────┐
  │ Step 1: 问题专家（sample_questions_balanced）                │
  │   集中出题：                                                │
  │     - 非聚焦模式：5个知识域各抽2题 → 10题                    │
  │     - 聚焦模式：全10题针对单一模块，强制LLM生成3道新题       │
  │   题目生成（generate_new_question_by_llm）：                 │
  │     调用DeepSeek，按模板输出问题+关键点+答案，解析后入库     │
  │     保存到 题集.json，每轮结束后持久化                       │
  │     题库自动增长（88→124+ 并持续扩展）                      │
  ├─────────────────────────────────────────────────────────────┤
  │ Step 2: RAG检索（rag_retrieve_v6）                          │
  │   a. BGE-large-zh-v1.5 向量检索 → Top-40                    │
  │   b. BM25关键词检索 → Top-40（通过hash去重合并）              │
  │   c. bge-reranker-v2-m3 精排 → Top-5                        │
  │   d. BM25结果通过hash→metadata映射表补全元数据                │
  ├─────────────────────────────────────────────────────────────┤
  │ Step 2.5: 答案生成（generate_rag_answer）                    │
  │   a. 上下文扩展（expand_chunk_context）：                    │
  │      对每个检索到的chunk，在ChromaDB中按source_file查找其     │
  │      在原文中的相邻段落（前后各2段），合并后喂给LLM           │
  │   b. DeepSeek基于扩展后的文档块生成简练回答（≤8000字符）      │
  ├─────────────────────────────────────────────────────────────┤
  │ Step 3: 四维度评分（score_one_v6）                           │
  │   ① faithfulness（忠实度，0-10）：                           │
  │      每个关键点逐条独立检索，用bge-reranker-v2-m3语义交叉打分 │
  │      sigmoid归一化（无温度参数），≥0.85标记"覆盖"            │
  │   ② answer_relevance（答案相关性，0-10）：                    │
  │      KP覆盖度×6 + 来源匹配×4                                 │
  │   ③ context_relevance（上下文相关性，0-10）：                 │
  │      来源匹配×5 + 排序质量×5                                  │
  │   ④ answer_accuracy（答案准确度，0-10）：                     │
  │      DeepSeek生成的RAG答案 vs 标准答案，用reranker语义匹配    │
  │   → 四维度取平均得总分                                        │
  ├─────────────────────────────────────────────────────────────┤
  │ Step 4: 模块聚焦决策                                         │
  │   - 计算各模块历史均分，选最低的作为 target_module            │
  │   - 模块均分≥9.0且最低分≥7.0 → fixed_modules 标记已修复      │
  │   - 全部模块修复或均分≥9.0 → 全局达标，结束                   │
  │   - 连续3轮均分下降 → 回退中止                                │
  ├─────────────────────────────────────────────────────────────┤
  │ Step 5: 失败案例分析师（analyze_failures_v4）                 │
  │   分析低分题的缺失模块和缺失关键点，输出补充指令               │
  ├─────────────────────────────────────────────────────────────┤
  │ Step 6: 文档生成（generate_supplement_chunks_v4）             │
  │   根据失败分析生成补充文档，含完整原文上下文和正则示例         │
  ├─────────────────────────────────────────────────────────────┤
  │ Step 7: 知识库写入（KnowledgeWriter）                        │
  │   向量化补充块→写入ChromaDB（去重）                          │
  └─────────────────────────────────────────────────────────────┘

循环控制：
  - 最多5轮（MAX_ROUNDS=5）
  - 每轮10题（QUESTIONS_PER_ROUND=10）
  - 回退中止：连续3轮均分下降则终止
  - 聚焦模式下每题集合都强制LLM生成新题（force_generate=3）

题库文件（项目根目录）：
  - 题集.json               — 测试题库（初始88题，LLM持续扩展）

7. 当前效果与瓶颈
================================================================================

当前最优效果（v7 模块聚焦 + LLM出题 + 上下文扩展）：
  - 最高均分：8.7（macros模块最后一轮）
  - 忠实度（faithfulness）：稳定 10.0（已达天花板）
  - 上下文得分（context）：稳定 10.0（BM25元数据回查修复）
  - 答案准确度（answer_accuracy）：0.1-9.9（波动取决于知识库覆盖度）
  - 第2-5轮聚焦模式下无单题低于7.0分

关键成果：
  - 题库自动增长：88 → 124+ 题（LLM主动生成+持久化）
  - 模块聚焦有效：macros模块从7题低分收敛到0题低分
  - 检索+reranker已充分发挥作用，忠实度/上下文分已到瓶颈

剩余瓶颈：
  - 答案准确度波动来自两个因素：
    ① SillyTavern-Docs对部分知识域的覆盖不完整
    ② LLM自生成的"标准答案"质量参差不齐（自问自评偏差）
  - 进一步推高需要：
    ① 扩充知识库（从更多渠道如ST社区wiki、GitHub issues抓取）
    ② 引入人工审核的标准答案队列，替代LLM自评
