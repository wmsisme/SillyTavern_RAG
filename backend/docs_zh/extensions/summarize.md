
# 摘要

## 这是什么？

此扩展允许您根据聊天中发生的事件创建、存储和使用自动生成的摘要。摘要有助于概述故事中正在发生的事件的一般细节，这*可以*被解释为长期记忆，但请谨慎对待这一说法。由于摘要是由语言模型生成的，输出可能会丢失一些重要细节或包含幻觉，因此建议您始终跟踪摘要状态，并在需要时手动更正。

## 通用配置

摘要扩展默认安装在 SillyTavern 中，因此它会出现在 ST 的扩展面板（堆叠立方体图标）列表中，如下所示：

![摘要配置面板](/static/extensions/summarize.png)

- **当前摘要** - 显示并提供修改当前摘要的能力。摘要在生成时会更新并嵌入到聊天文件的元数据中，该元数据对应于摘要生成时处于上下文中的最后一条消息。从聊天中删除或编辑附加了摘要的消息，会将状态回滚到上一个有效的摘要。
- **恢复上一个** - 删除当前摘要，将其回滚到之前的状态。当摘要器在某个特定时间点表现不佳时，此功能很有用。
- **暂停** - 勾选此选项可防止摘要自动更新。如果您想提供自己的自定义摘要，或者通过清空文本框并停止更新来有效禁用摘要，此功能很有用。
- **弹出窗口** - 允许将摘要分离到侧边栏上可移动的 UI 面板中。在桌面布局中很有用，可以轻松访问摘要设置，而无需通过扩展菜单导航。
- **注入模板** - 定义摘要插入到常规聊天提示中的包装方式。应使用特殊的 \{\{summary\}\} 宏来表示当前摘要状态在提示注入文本中的确切位置。
- **注入位置** - 设置提示注入的位置。选项与作者笔记相同：在主提示之前或之后，或在指定深度的聊天内部。

## 支持的摘要来源

### 主 API

摘要将由您当前选择的 AI 后端、模型和设置提供支持。此方法无需额外设置，只需一个有效的 API 连接。

此选项具有以下子模式，它们根据摘要提示的构建方式而有所不同：

1. **原始，阻塞式**。摘要将仅使用摘要提示和聊天历史生成。后续提示还将包括之前的摘要以及摘要生成后发送的消息（参见示例）。此模式可以（并且将会）生成在提示之间具有很大差异性的提示，因此不建议将其与提示处理速度较慢的后端（如 llama.cpp 及其衍生版本）一起使用。
2. **原始，非阻塞式**。与上述相同，但在摘要生成期间不会阻塞聊天生成。并非所有后端都支持同时请求，因此如果摘要失败，请切换到阻塞模式。
3. **经典，阻塞式**。摘要提示将作为中性系统指令附加在常规生成提示的末尾，不会省略角色卡、主提示、示例对话以及聊天提示的其他部分。这通常会产生与重用已处理提示兼容性良好的提示，因此建议与 llama.cpp 及其衍生版本一起使用。

#### 摘要设置说明

1. **摘要提示** - 定义用于创建摘要的提示。可以包含任何已知的宏，以及特殊的 \{\{words\}\} 宏（见下文）。
2. **目标摘要长度（词）** - 定义 \{\{words\}\} 宏的值，该宏可插入到摘要提示中。此设置完全可选，如果未使用该宏，则没有任何效果。
3. **API 响应长度（令牌）** - 允许为生成摘要设置一个覆盖全局设置的 API 响应长度。
4. **每次请求的最大消息数（仅原始模式）** - 设置限制，以限制一次摘要提示中将包含的最大消息数。`0` 表示没有明确限制，但最终要摘要的消息数量仍取决于最大上下文大小，计算公式为：`最大摘要缓冲区 = 上下文大小 - 摘要提示 - 上一个摘要 - 响应长度`。当您希望在使用大上下文大小的模型时获得更聚焦的摘要时，请使用此选项。
5. **不包含世界信息/作者笔记** - 从要摘要的文本中省略世界信息和作者笔记。仅在经典提示构建器中生效。原始提示构建器始终省略世界信息/作者笔记。
6. **每 X 条消息更新一次** - 设置生成摘要的间隔。`0` 表示禁用自动摘要，但您仍然可以通过单击“立即摘要”按钮手动触发摘要。此值应根据提示缓冲区被聊天消息填满的速度进行调整。理想情况下，您希望当消息开始被排除在提示之外时生成第一个摘要。
7. **每 X 个词更新一次** - 与上述相同，但使用词（而不是令牌！）代替消息。理论上，由于聊天消息的内容通常不可预测，这可能是一种更准确的度量方式，但效果可能因情况而异。

如果两个“每...更新”滑块都设置为非零值，则两者都会根据各自的时间间隔触发摘要更新，具体取决于哪个先发生。强烈建议在切换到具有不同上下文大小的另一个模型时相应地更新这些值，否则摘要生成可能会触发过于频繁，或者根本不触发。

如果您对间隔设置不确定，可以单击“每...更新”滑块上方的“魔法棒”按钮，尝试根据一些简单的启发式规则猜测最佳值。算法的简要描述如下：

1. 计算所有聊天消息的令牌数和词数
2. 根据所需的提示词数确定目标摘要长度
3. 根据平均消息长度计算提示中能容纳的最大消息数
4. 如果设置了“最大消息数”，则调整平均值以考虑不适合摘要限制的消息
5. 将调整后的每次提示平均消息数向下取整到 5 的倍数


### Extras API

带有 `summarize` 模块的 Extras 服务器可以运行一个辅助摘要模型（BART）。

它的上下文大小非常小（约 1024 个令牌），因此处理大型摘要的能力相当有限。

要配置 Extras 摘要源，请执行以下操作：

1. 安装或更新 [Extras](https://github.com/SillyTavern/SillyTavern-extras) 到最新版本。
2. 运行启用了 `summarize` 模块的 Extras：`python server.py --enable-modules=summarize`

#### 更改摘要模型

默认情况下，摘要使用 [Qiliang/bart-large-cnn-samsum-ChatGPT_v3](https://huggingface.co/Qiliang/bart-large-cnn-samsum-ChatGPT_v3) 模型进行摘要。

可以通过使用命令行参数 `--summarization-model=(###Hugging-Face-Model-URL-Here###)` 来更改此设置。

一个已知的备用摘要模型是 `Qiliang/bart-large-cnn-samsum-ElectrifAi_v10`。
