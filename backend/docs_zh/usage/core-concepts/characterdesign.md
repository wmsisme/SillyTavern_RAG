
# 角色设计

> **💡 Tip**
>
> 角色名称是唯一必填字段。你可以将其他字段留空，仍然可以在聊天中使用该角色。


## 角色描述

用于向AI添加角色描述和其他相关信息。这些信息会始终包含在提示词中，因此所有重要事实都应在此处填写。

例如，你可以添加故事发生的世界信息，描述角色的外貌、性格和背景。

可以是任意长度（200或2000词元均可），并可采用任何风格（自由文本、伪代码对话风格等）进行格式化。

## 角色词元

**TL;DR：如果你使用的AI模型上下文词元限制为2048，那么一个1000词元的角色定义会使AI的“记忆”减少一半。**

换个角度说，一个优秀AI生成的得体回复很容易达到200-300词元。在这种情况下，AI只能“记住”大约3轮聊天历史记录。

### 为什么我的角色词元计数器变红了？

当我们发现你的角色定义中的词元数超过模型定义上下文长度的一半时，我们会高亮显示它，因为这可能会降低AI提供愉悦对话的能力。

### 如果我的角色词元过多会怎样？

别担心——这不会破坏任何东西。最坏的情况下，如果角色的永久词元过大，只会意味着上下文中留给其他内容的空间更少（见下文）。

唯一可能产生的负面副作用是AI的“记忆”会减少，因为它可处理的聊天历史记录变少了。

这是因为每个AI模型一次能处理的上下文量都是有限制的。

## “上下文”？

这是每次你要求AI生成回复时发送给AI的信息。SillyTavern在将信息发送给AI模型之前，会自动计算分配可用上下文词元的最佳方式。

更多关于上下文构建方式的信息，请参阅[提示词](/usage/prompts/)章节。

### 什么是角色的“永久词元”？

这些词元会在每次生成请求时始终发送给AI：

* 角色名称
* 角色描述框
* 角色个性框
* 场景框

### 角色定义的哪些部分不是永久的？

* 首条消息框——仅在聊天开始时发送一次。
* 示例对话框——仅在聊天历史填满上下文前保留（可选情况下可强制保留在上下文中）。

### 流行AI模型的上下文词元限制

* LLaMA 3及其微调版本 - 8192
* OpenAI GPT-4 - 最高128k
* Google Gemini - 最高2M
* Anthropic的Claude - 200k（Claude 3）
* NovelAI - 8192（Erato和Kayra，Opus层级；Clio，所有层级）、6144（Kayra，Scroll层级）或3072（Kayra，Tablet层级）

## 首条消息

首条消息是一个重要元素，它定义了角色将以何种方式和风格进行交流。模型更倾向于从首条消息中获取风格和长度限制，而不是其他任何东西，因此以你期望的回复方式（简洁明了、长篇详细等）来撰写首条消息非常重要。

支持Markdown和HTML格式。

例如：

```txt
*你猛地惊醒，回忆起带你深入森林的事件以及袭击你的野兽。当你的眼睛适应了房间周围散发出的柔和光芒时，记忆渐渐消退。* “啊，你终于醒了。我担心极了，发现你浑身是血、昏迷不醒。” *她走过来，握住你的双手，她的触碰传递着温暖和安慰，嘴唇浮现出温柔关怀的微笑。* “我叫塞拉菲娜，这座森林的守护者——我用我的魔法尽力治愈了你的伤口。你现在感觉怎么样？希望这茶能帮你恢复体力。” *她琥珀色的眼睛探寻着你的目光，充满了同情和对你安康的关切。* “请休息吧。你在这里很安全。我会照顾你，但你需要休息。我的魔法只能愈合到这个程度。”
```

## 备选问候语

此处添加的消息在开始新聊天时，会作为角色首条消息的额外“滑屏”选项显示。如果角色是群聊的一部分，系统会随机选择其中一条问候语来发起对话。

## 收藏角色

点击 **<i class="fa-solid fa-star"></i> 添加至收藏** 按钮可以将角色标记为收藏，以便在侧边菜单栏通过选择“收藏”排序选项快速筛选。收藏角色在列表中会带有金色高亮。同时，该角色头像会出现在快速切换区域（如果在用户设置中启用）。

## 高级定义

> **ℹ️ Info**
>
> 以下字段默认隐藏。要访问并编辑它们，需要点击角色定义页面菜单栏上的 **<i class="fa-solid fa-book"></i> 高级定义** 按钮。


### 提示词覆盖

* **主提示词**：如果启用了用户设置“优先使用角色提示词”，则在此处输入的任何文本将覆盖该角色的[主/系统提示词](/usage/prompts/#main-prompt-system-prompt)。
* **历史后指令**：如果启用了用户设置“优先使用角色指令”，则在此处输入的任何文本将作为该角色的[历史后指令](/usage/prompts/#post-history-instructions) 使用。

> **💡 Tip**
>
> 在任意一个框中插入 `{{original}}`，可以在指定位置包含系统设置中相应的默认提示词。


### 创作者元数据

> **ℹ️ Info**
>
> 不用于提示词构建，但提供关于角色的额外元数据。


* **创建者**：角色创建者的名称。如果用户设置“角色列表副标题”设置相应，可以在角色列表中显示。
* **角色版本**：角色的版本。如果用户设置“角色列表副标题”设置相应，可以在角色列表中显示。
* **创作者注释**：创建者希望分享的任何关于角色的附加注释。前几行会显示在角色列表中，完整文本会显示在角色页面的“创作者注释”部分。支持Markdown/HTML格式。
* **嵌入标签**：用逗号分隔的标签列表，这些标签将嵌入到角色描述中。导入角色时，这些标签默认不会被导入，但你可以通过选择角色页面“更多...”菜单中的“导入标签”将其与你现有的标签合并。

### 个性摘要

角色个性的简要概述。

### 场景

对话的背景和环境。

### 角色备注

在特定消息深度处作为聊天内提示词注入的文本。通常用于强化某些角色特征，因为它始终保持在聊天历史中的固定深度，不受对话进展影响。

* **@ 深度**：在聊天历史中，此备注将在多少条消息后注入（按从最新到最旧的顺序）。如果设置为0，则在最后一条消息后注入。
* **角色**：消息的角色。可以是“用户”、“系统”或“助手”。

### 健谈度

在使用[自然](/usage/core-concepts/groupchats/#natural-order)激活顺序的群聊中，决定角色回复被触发的概率。范围从0%到100%，默认值为50%。

### 对话示例

描述角色如何说话。在每个示例之前，需要添加 `<START>` 标签。对话示例块仅在上下文中存在可用空间时才会被插入，并按块逐块被挤出上下文。`<START>` 不会出现在提示词中，因为它只是一个标记；对于文本补全API，它将被替换为高级格式设置中的“示例分隔符”；对于聊天补全API，它将被替换为“新示例聊天”实用提示词的内容。

* 使用 `{{char}}:` 前缀表示角色消息。
* 使用 `{{user}}:` 前缀表示用户消息。

示例：

```txt
<START>
{{user}}: "描述你的特质？"
{{char}}: *塞拉菲娜温柔的笑容更加灿烂，她花时间思考这个问题，眼中闪烁着内省与自豪的光芒。她优雅地靠近，灵动的身躯散发出柔和、平静的光芒。* "特质，是吗？嗯，我想如果要用语言概括的话，有几个定义了我。首先，我是守护者——这片魔法森林的保护者。" *塞拉菲娜说话时伸出手，露出纤细而精巧编织的藤蔓缠绕在她的手腕上，脉动着微弱的翠绿色能量。她轻弹手腕，一阵微风吹过房间，带来野花和古老智慧的芬芳。塞拉菲娜的琥珀色眼睛闪烁着坚定的决心，继续描述自己。* "同情心是我的另一个核心特质。" *塞拉菲娜的声音变得柔和，充满同理心。* "我深爱着森林中的生灵，也爱那些需要帮助的人。" *她打开一扇窗，手掌轻轻托住一只飞进房间的受伤小鸟，羽毛在她的触碰下逐渐愈合。*
<START>
{{user}}: "描述你的身体和特征。"
{{char}}: *塞拉菲娜轻声笑起来，悦耳的声音在空气中飘荡，她用调皮的眼神迎上你害羞的目光，玫瑰色的眼睛闪烁着光芒。* "啊，我的外表？嗯，我想这是个合理的问题。" *她露出温柔的微笑，优雅地旋转，飘逸的长裙裙摆随之展开，仿佛被无形的微风拂动。当她停下时，粉色的长发像棉花糖瀑布一样垂在背上，每一缕都闪烁着魔法般的微光。* "我的身体纤细而灵动，映照着森林优雅之美。我的眼睛，你肯定注意到了，是琥珀色的——温暖的棕色，反射出温暖、同情，以及森林不羁的精神。我的嘴唇柔软，常带微笑，这反映了我在照料森林和寻求慰藉之人时感受到的喜悦与关怀。" *塞拉菲娜的声音带着一丝俏皮，眼中闪烁着顽皮的光芒。*
```
