
# 世界信息

**世界信息（也称为传说书或记忆书）是 ST 中一个强大的工具，可以动态地将提示插入到你的聊天中，以帮助引导 AI 的回复。**

通常，世界信息（简称 WI）用于增强 AI 对你虚构世界中细节的理解，不过你也可以使用世界信息条目来插入任何你想要插入到提示中的内容。

它的功能类似于一个动态词典，只有当与条目关联的关键词出现在消息文本中时，才会从世界信息条目中插入相关信息。

SillyTavern 引擎会激活并将相应的传说无缝集成到提示中，为 AI 提供背景信息。

*需要注意的是，虽然世界信息有助于引导 AI 朝着期望的内容方向发展，但它并不能保证生成输出消息中一定会出现这些内容。这取决于你的模型利用附加信息的能力有多强！*

## 专业提示

* 世界信息引擎是一个非常强大的提示管理工具。不要只局限于添加角色传说，可以随意尝试。
* 激活关键词、标题以及其他不在**内容**字段中的信息不会被插入到上下文中，因此每个世界信息条目都应该有一个全面、独立的描述。
* 要创建丰富而详细的世界传说，条目之间可以通过递归激活相互链接和引用。详见下方的[递归](#递归扫描)。
* SillyTavern 为插入的背景信息提供了灵活的上下文预算。为了节省提示 token，建议保持条目内容简洁。

## 上下文特定来源

除了全局世界信息选择器之外，传说书还可以分配给特定的上下文——某个角色、某个角色扮演身份或某个单独的聊天。当相关的角色、角色扮演身份或聊天处于活动状态时，这些上下文特定来源会自动激活。

### 角色传说

可选地，世界信息文件可以分配给一个角色，作为该角色所有聊天（包括群组聊天）中的专用传说来源。

一个主要的世界信息可以绑定到角色。要执行此操作，请导航到角色管理面板并点击地球按钮，然后从下拉列表中选择世界信息并点击“确定”。导出角色时，此文件也会嵌入到角色卡数据中。

要解绑、更改或分配额外的世界信息文件作为角色传说，请按住 Shift 点击地球按钮，或点击“更多...”然后点击“链接世界信息”。请注意，只有主要世界信息文件会随角色一起导出。

重命名世界信息文件时，系统会提示你选择是否在所有引用该传说书的角色中重新链接。这确保了在重命名后现有的角色传说绑定保持完好。

### 角色扮演身份传说书

世界信息文件可以分配给当前活动的[角色扮演身份](/usage/core-concepts/personas/)。每当选择该角色扮演身份时，无论打开的是哪个角色或聊天，该传说书中的条目都会被激活。

要将传说书分配给角色扮演身份，请打开**角色扮演身份管理**面板并点击 <i class="fa-solid fa-globe"></i> **角色扮演身份传说**按钮。从下拉列表中选择一个世界信息文件。如果已经绑定了传说书，点击该按钮会直接打开传说书编辑器。

> **📝 提示**
当已经绑定了传说书时，要重新打开分配弹窗，请在角色扮演身份传说按钮上使用**长按**（移动端）或 **Shift+点击 / Alt+点击**（桌面端）。
> **📝 提示**

### 聊天传说书

世界信息文件也可以分配给单个聊天。聊天绑定的传说书中的条目仅在该特定对话中有效，不会延续到同一角色的其他聊天中。

要将传说书分配给聊天，请点击角色管理面板中的 <i class="fa-solid fa-passport"></i> **聊天传说**按钮。从下拉列表中选择一个世界信息文件。如果已经绑定了传说书，点击该按钮会直接打开传说书编辑器。

> **📝 提示**
当已经绑定了传说书时，要重新打开分配弹窗，请在聊天传说按钮上使用**长按**（移动端）或 **Shift+点击 / Alt+点击**（桌面端）。
> **📝 提示**

### 传说插入策略

生成 AI 回复时，来自角色世界信息和其他辅助来源的条目将与全局世界信息选择器中的条目合并。默认情况下，条目将按以下顺序插入：

* [聊天传说](#聊天传说书)
* [角色扮演身份传说](#角色扮演身份传说书)
* 角色传说或全局传说，使用以下策略之一：

#### 均匀排序（默认）

所有条目将按照其插入顺序排序，就像它们是同一个大文件的一部分一样，忽略来源。

#### 角色传说优先

来自角色世界信息的条目将按其插入顺序优先包含，然后是来自全局世界信息的条目。

#### 全局传说优先

来自全局世界信息的条目将按其插入顺序优先包含，然后是来自角色世界信息的条目。

## 世界信息条目

### 关键词

触发世界信息条目激活的关键词列表。默认情况下关键词不区分大小写（这是[可配置的](#区分大小写关键词)）。

#### 正则表达式（Regex）作为关键词

关键词支持正则表达式，从而实现更灵活的匹配方式。这使得可以用可选词或字符、间距以及正则表达式提供的所有其他功能来匹配更动态的内容。
如果定义的关键词是有效的正则表达式（JavaScript 正则风格，以 `/` 作为分隔符。允许所有标志），在检查条目是否应被触发时，它将被视为正则表达式。多个正则表达式可以作为单独的关键词输入，并且会同时生效。在正则表达式内部，逗号是可以使用的。纯文本关键词不支持逗号，因为逗号被视为关键词分隔符。

高级正则匹配的一个用例示例：
当角色在做与天气相关的动作时，应该插入的条目/指令

```js
/(?:{{char}}|he|she) (?:is talking about|is noticing|is checking whether|observes) (?:the )?(rainy weather|heavy wind|it is going to rain|cloudy sky)/i
```

有关正则表达式语法和可能性的更多信息：[正则表达式 - JavaScript | MDN](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Regular_expressions)

##### 高级逐消息正则匹配

ST 在 WI 扫描缓冲区中为每条聊天消息添加前缀 `character name:`，并且在 v1.12.6 之后，使用字符值 1（`\x01`）作为前缀。
这意味着你可以使用与该分隔字符绑定的正则表达式来匹配特定角色的特定输入或输出。

例如，要仅匹配用户说“hello”，你可以使用以下正则表达式：

```js
/\x01{{user}}:[^\x01]*?hello/
```

#### 关键词输入

有两种输入关键词的模式，每种模式的 UI 略有不同。在 ⌨️ *纯文本模式*（默认）下，关键词可以在单个文本字段中以逗号分隔列表的形式输入。也可以包含正则表达式，但它们不会有任何特殊高亮。在 ✨ *花式模式*下，关键词显示为单独的元素，正则表达式会相应地高亮显示。该控件支持编辑和删除关键词。可以通过输入控件内的内联按钮切换模式。

### 可选过滤器

与主关键词配合使用的附加关键词的逗号分隔列表。
如果未提供参数，则忽略此标志。
支持 AND ANY、NOT ANY 或 NOT ALL 逻辑

1. AND ANY = 仅当主关键词和任意一个可选过滤关键词出现在扫描上下文中时，才激活该条目。
2. AND ALL = 仅当主关键词和所有可选过滤关键词都存在时，才激活该条目。
3. NOT ANY = 仅当主关键词存在且没有任何可选过滤关键词出现在扫描上下文中时，才激活该条目。
4. NOT ALL = 如果所有可选过滤器都出现在扫描上下文中，则即使主关键词触发，也阻止该条目激活。

这些关键词也支持[正则表达式](#正则表达式regex作为关键词)。

### 条目内容

条目激活时插入到提示中的文本。

### 插入顺序

数值。定义当多个条目同时被激活时条目的优先级。顺序号较大的条目将被插入到更接近上下文末尾的位置，因为它们对输出的影响更大。例如，顺序号为 100 的条目将出现在顺序号为 250 的条目之前。

### 插入位置

* **角色定义之前：** 世界信息条目插入在角色描述和场景之前。对对话有中等影响。
* **角色定义之后：** 世界信息条目插入在角色描述和场景之后。对对话有较大影响。
* **示例消息之前：** 世界信息条目被解析为示例对话块，并插入在角色卡提供的示例之前。
* **示例消息之后：** 世界信息条目被解析为示例对话块，并插入在角色卡提供的示例之后。
* **作者注释顶部：** 世界信息条目插入在作者注释内容的顶部。影响程度取决于作者注释的位置。
* **作者注释底部：** 世界信息条目插入在作者注释内容的底部。影响程度取决于作者注释的位置。
* **@ D：** 世界信息条目插入在聊天中的特定深度（深度 0 为提示的底部）。
  * ⚙️ - 作为系统角色消息
  * 👤 - 作为用户角色消息
  * 🤖 - 作为助手角色消息
* **出口：** 世界信息条目不会自动注入。相反，其内容存储在一个命名出口下，这样你可以通过使用 [`{{outlet::名称}}` 宏](#出口名称)来决定它在提示中出现的准确位置。

示例消息条目将根据提示构建设置进行格式化：指令模式或聊天补全提示管理器。它们也遵循示例消息行为规则：在上下文满时逐渐推出、始终保留或完全禁用。

如果你的作者注释被禁用（插入频率 = 0），则位于作者注释位置的世界信息条目将被忽略！

### 出口名称

当选择**出口**插入位置时，条目会额外显示一个**出口名称**字段。你在此处提供的名称将条目分组在一起，并定义了你将用于手动将它们拉入提示的 token。

在[提示管理器](/usage/prompts/prompt-manager/)或[高级格式化](/usage/core-concepts/advancedformatting/)提示字段中使用 `{{outlet::你的名称}}` 宏。当提示构建时，该宏将被替换为所有共享相同出口名称的世界信息条目的合并内容，以换行符分隔，按其[插入顺序](#插入顺序)值排序。

如果出口条目缺少名称，它将在生成过程中被跳过，因此请确保填写该字段。出口名称支持基于你已使用过的名称进行自动补全，以便轻松复用一致的标签。

#### 限制和注意事项

* 不支持在世界信息条目内部放置出口宏，这样做不会生效。这与世界信息的求值顺序冲突，可能导致无限循环。
* 不支持嵌套出口。你不能在一个出口的内容中放置另一个出口的宏。与上述相同，这可能导致无限循环。
* 角色卡字段（描述、性格、场景等）无法展开出口。这些字段会被提前解析，以便它们可以作为世界信息触发的[附加匹配来源](#附加匹配来源)，这意味着当它们的文本被处理时出口不可用。如果你需要将出口内容放在提示正文中，请使用另一个支持宏的字段。
* 作者注释编辑器也无法解析出口。要将出口内容放置在作者注释周围，请将条目分配到**作者注释顶部**或**作者注释底部**插入位置，而不是依赖宏。
* 出口名称区分大小写。`{{outlet::}}` 宏必须使用与条目的**出口名称**完全相同的大小写，否则不会返回任何内容。
* 当你调用宏时，出口名称中的前导或尾随空格会被忽略，因此保存时带有额外空白的名称将无法匹配。避免在名称中添加填充空格，以便它们能被正确解析。
* 没有分配内容的出口宏将被替换为空字符串。

### 条目标题 / 备注

一个供你方便地标记条目的文本字段，AI 或任何触发逻辑都不会使用它。

如果为空，可以通过点击“填充空备注”按钮使用条目的第一个关键词来回填。

### 策略

1. 🔵（蓝色圆圈）= 该条目不需要任何关键词，无论内容如何都会触发。
2. 🟢（绿色圆圈）= 该条目仅在关键词存在时才会被触发。
3. 🔗（链环）= 该条目允许通过嵌入相似度插入。

每个条目还有一个开关，允许你启用或禁用该条目。

### 概率（触发 %）

此值充当额外的过滤器，当条目通过任何方式（常量、主关键词、递归）被激活时，增加其不被插入的几率。

1. 概率 = 100 表示该条目在每次激活时都会被插入。
2. 概率 = 50 表示该条目有 1:1 的几率被插入。
3. 概率 = 0 表示该条目不会被插入（实际上是禁用它）。

使用此功能在你的聊天中创建随机事件。例如，每条消息都可能有 1% 的几率在提到某个古神的名字时唤醒它。

### 包含组

包含组控制当多个具有相同组标签的条目同时被触发时如何选择条目。如果多个具有相同组标签的条目被激活，只有一个会被插入到提示中。

默认情况下，被选中的条目根据其组权重（默认为 100 点）随机选择——数字越高，被选中的概率越高。这允许在已触发的条目中进行随机选择，为交互增添惊喜和多样性。

如果以逗号分隔列表的形式定义，单个条目可以属于多个包含组。将适用与上述相同的逻辑。如果该条目被触发，它将*禁用*属于其任何组的所有其他条目。因此，如果任何组被激活，该条目将不会被激活。

### 优先包含

为了对通过[包含组](/usage/core-concepts/worldinfo/#包含组)激活哪些条目提供更多控制，你可以使用“优先包含”设置。此选项允许你确定性地指定选择哪个条目，而不是随机掷组权重概率。

如果多个具有相同组标签且启用了此设置的条目被激活，将选择“顺序”值最高的那个。这对于通过包含组创建回退序列很有用。例如，优先选择深度较低但强调更多的条目，或者在两个都有效的情况下选择特定的场景设置指令而非另一个。

### 使用组评分

当全局或逐条目启用此设置时，已激活条目关键词的数量决定组获胜者的选择。只有组中关键词匹配数最高的子集会被保留，由组权重或包含优先级决定是否激活——其余的将被停用并从组中移除。

使用此功能为大型组中的单个条目提供更多特异性。例如，它们可以有一个通用关键词和一个特定关键词。当未提供特定关键词时，将随机插入一个条目，反之亦然。

主关键词的分数计算逻辑为 1 次匹配 = 1 分。

对于次要关键词，交互取决于所选择的选择性逻辑：

1. AND ANY：1 次次要匹配 = 1 分。
2. AND ALL：如果所有次要关键词都匹配，每个次要关键词得 1 分。
3. NOT ANY 和 NOT ALL：无变化。

示例：

* 条目 1。关键词：song、sing、Black Cat。组：songs
* 条目 2。关键词：song、sing、Ghosts。组：songs

输入 `sing me a song` 可以激活任一条目（两者都激活了 2 个关键词），但 `sing me a song about Ghosts` 只会激活条目 2（激活了 3 个关键词）。

### 自动化 ID

允许将世界信息条目与快速回复扩展中的 [STscripts](/usage/st-script/) 集成。如果快速回复命令和 WI 条目具有相同的自动化 ID，当具有匹配 ID 的条目被激活时，该命令将自动执行。

自动化按触发顺序执行，遵循你指定的排序策略，结合[角色传说插入策略](#角色传说插入策略)和“优先级”排序。这导致[蓝色圆圈](#策略)条目首先被处理，然后其他条目按其指定的“顺序”处理。递归触发的条目将在之后以相同顺序处理。

如果多个具有相同自动化 ID 的条目被激活，脚本命令只会运行一次。

### 角色过滤器

此条目可以为其激活的角色名称列表。如果此列表不为空，该条目将仅对名称在列表中的角色激活。当选择了一个标签时，该条目将仅对具有该特定标签的角色激活。

“排除”模式会反转过滤器，意味着该条目将对除添加到列表中或具有所选标签之外的所有角色激活。

### 触发类型

此世界信息条目可以为其激活的生成类型。如果未选择任何内容，该条目可以为其所有生成类型激活。如果选择了一个或多个，该条目将仅对以下特定生成类型激活：

* **正常：** 常规消息生成请求。
* **继续：** 当按下继续按钮时。
* **扮演：** 当按下扮演按钮时。
* **滑动：** 当通过滑动触发生成时。
* **重新生成：** 在单人聊天中按下重新生成按钮时。
* **静默：** 后台生成请求，通常由[扩展](/extensions/)或 [STscript](/usage/st-script/) 命令触发。

> **📝 提示**
“重新生成”触发器在群组聊天中不可用，因为它使用不同的重新生成逻辑：最后一条回复的所有消息都会被删除，消息根据所选的[群组回复策略](/usage/core-concepts/groupchats/#回复顺序策略)使用“正常”生成类型排队。
> **📝 提示**

### 附加匹配来源

默认情况下，世界信息条目仅与当前对话的内容进行匹配。这些选项允许你将条目与不会出现在聊天中的不同角色信息，甚至角色扮演身份信息进行匹配。当你希望拥有可在多个角色之间使用的广泛条目，但又不想管理大量标签列表，或者不想每次创建新角色时都更新角色过滤列表时，这非常有用。这也允许你根据当前激活的角色扮演身份来匹配条目。

* **角色描述**：与角色描述进行匹配。
* **角色性格**：与角色性格摘要进行匹配，位于高级定义下。
* **场景**：与角色指定的场景进行匹配，位于高级定义下。
* **角色扮演身份描述**：与当前所选角色扮演身份的描述进行匹配。
* **角色备注**：与角色备注进行匹配，可在高级定义下找到。
* **创作者备注**：与角色创作者备注进行匹配，可在高级定义下找到。创作者备注通常不会包含在提示中。

## 向量存储匹配

向量存储扩展通过使用最近聊天消息与世界信息条目内容之间的相似度，提供了关键词匹配的替代方案。

要启用和使用此功能，需要满足以下前提条件：

1. 向量存储扩展已启用，并配置为使用可用的嵌入来源之一。
2. 在向量存储扩展设置中勾选了“为世界信息启用”复选框。
3. 允许无关键词匹配的世界信息条目具有“向量化”（🔗）状态，或者在向量存储设置中勾选了“为所有条目启用”选项。

此处不会涵盖扩展中向量化模型的选择以及“嵌入”一词背后的理论含义。如果你需要有关此主题的更多信息，请查看[数据库](/usage/core-concepts/data-bank/#向量存储)指南。

向量存储匹配遵循以下规则：

* 允许与向量存储匹配的最大条目数可以通过“最大条目数”设置进行调整。此数字仅设置限制，不会影响世界信息激活设置中设置的 token 预算。所有预算规则仍然适用。
* 此功能仅替代关键词检查。条目必须满足所有附加检查才能被插入：触发百分比、角色过滤器、包含组等。
* 不使用激活设置或条目覆盖中的“扫描深度”设置。而是使用向量存储的“查询消息”值来获取要匹配的文本。这允许将“扫描深度”设置为 0 的配置，这样不会进行常规关键词匹配，但条目仍然可以通过向量激活。
* “向量化”状态只是一个附加标记。如果设置了关键词，该条目的行为仍然像正常的、已启用的、非常量记录一样，会通过关键词激活。如果你希望它们仅通过向量激活，请移除关键词。

> **ℹ️ 注意**
>
> 由于检索质量完全取决于嵌入模型的输出，无法准确预测哪些条目会被插入。如果你想要确定性和可预测的结果，请坚持使用关键词匹配。


## 定时效果

通常，世界信息求值是无状态的，意味着求值结果仅取决于当前聊天上下文。然而，通过引入定时效果，你可以创建具有激活延迟、触发后保持活跃、或激活后无法再被触发的条目。

### 定时效果规则

1. 效果的时间范围以消息为单位（不是消息对/交换），0 表示没有效果。
2. 效果仅在条目被激活的聊天中生效。分支继承父聊天的状态。
3. 如果聊天没有推进，例如最后一条消息被滑动或删除，活动的定时效果将被移除。
4. 对当前处于定时效果中的条目进行任何更改都将导致效果被强制移除。
5. 如果效果已经激活，后续关键词触发不会刷新效果持续时间。

### 定时效果类型

1. 粘性 - 条目在激活后保持活跃 N 条消息。在过期之前，粘性条目在后续扫描中忽略概率检查。
2. 冷却 - 条目在激活后 N 条消息内无法被激活。可以与粘性一起使用：当粘性持续时间结束时，条目进入冷却。
3. 延迟 - 除非在求值时聊天中至少有 N 条消息，否则条目无法被激活。
    * 延迟 = 0 -> 条目可以在任何时候被激活。
    * 延迟 = 1 -> 如果聊天为空（没有问候语），条目无法被激活。
    * 延迟 = 2 -> 如果聊天中只有零条或一条消息，条目无法被激活，以此类推。

### 定时效果示例

条目配置：粘性 = 3，冷却 = 2，延迟 = 2。

```txt
消息 0：延迟
消息 1：条目激活
消息 2：粘性
消息 3：粘性
消息 4：粘性
消息 5：冷却
消息 6：冷却
消息 7：条目可以再次被激活
```

## 激活设置

世界信息屏幕顶部的可折叠菜单。

### 扫描深度

> 可以在条目级别覆盖。

定义应扫描多少条聊天历史消息以查找世界信息关键词。

* 如果设置为 0，则仅求值递归条目和作者注释。
* 如果设置为 1，则 SillyTavern 仅扫描最后一条消息。
* 2 = 最后两条消息，以此类推。

### 包含名称

定义聊天参与者的名称是否应作为消息前缀包含在扫描文本缓冲区中。这允许激活使用名称作为关键词的条目，而无需在消息中直接提及名称。

请参阅下方要扫描的文本示例，假设聊天参与者名为 Alice 和 Bob。

启用（默认）：

```txt
Alice: Hello! Good to see you.
Bob: How is the weather today?
```

禁用：

```txt
Hello! Good to see you.
How is the weather today?
```

### 上下文 % / 预算

**定义世界信息条目一次可以使用多少 token。**
你可以定义相对于 API 最大上下文设置的阈值（上下文 %）或客观的 token 阈值（预算）

如果预算耗尽，即使关键词存在于提示中，也不会再激活更多条目。

常量条目将首先被插入。然后是顺序号较大的条目。

通过直接提及关键词插入的条目比在其他条目内容中提及的条目具有更高的优先级。

### 最小激活数

**此设置与最大递归步数互斥。**

最小激活数：如果设置为非零值，这将忽略“扫描深度”的限制，从最新消息向后搜索整个聊天记录以查找关键词，直到触发了最小激活数指定的条目数量。这仍将受到最大深度设置或整体预算上限的限制。

*由最小激活数触发的额外扫描不会检查之前步骤中通过递归添加的条目。只有聊天消息和扩展提示可以触发这些额外的激活。但是，由最小激活数激活的条目可以像往常一样触发其他条目。*

### 最大深度

使用最小激活数设置时扫描的最大深度。

### 递归扫描

递归扫描允许条目激活其他条目或被其他条目激活，从而实现不同世界信息条目之间的复杂交互和依赖关系。此功能可以显著增强你的创意场景的动态性。
是否启用递归扫描可以通过全局设置**递归扫描**来控制。
有三个选项可用于控制每个条目的递归：

* **不可递归**：选中此复选框时，该条目不会被其他条目激活。这对于不应改变或受其他世界信息条目影响的静态信息很有用。

* **阻止进一步递归**：选择此选项可确保一旦此条目被激活，它不会触发任何其他条目。这有助于避免意外的激活链。

* **延迟到递归**：此条目仅在递归检查期间被激活，意味着它不会在初始扫描中被触发，但可以被其他启用了递归的条目激活。现在，通过为这些延迟添加**递归层级**，条目按层级分组。最初，只有第一层（最小数字）会被匹配。一旦找不到匹配项，下一层就有资格进行匹配，重复该过程直到检查完所有层级。这允许在递归期间更好地控制更深层信息的揭示方式和时机，特别是与 NOT ANY 或 NOT ALL 关键词匹配组合条件结合使用时。

**条目可以通过在内容文本中提及其关键词来激活其他条目。**

例如，如果你的世界信息包含两个条目：

```txt
条目 #1
关键词：Bessie
内容：Bessie 是一头牛，和 Rufus 是朋友。
```

```txt
条目 #2
关键词：Rufus
内容：Rufus 是一只狗。
```

如果消息文本**仅**提到 **Bessie**，**两者**都会被拉入上下文。

### 最大递归步数

**此设置与最小激活数互斥。**

当设置为零时，递归嵌套仅受提示预算限制。当设置为非零值时，将总扫描次数限制为所需的最大“嵌套层级”。

示例值：

* 1 实际上禁用递归，因为检查在第一步后停止。
* 2 只能激活递归条目一次。
* 3 可以触发递归两次...

### 区分大小写关键词

> 可以在条目级别覆盖。

**要被拉入上下文，条目关键词需要与其在世界信息条目中定义的大小写匹配。**

当你的关键词是常见词或常见词的一部分时，这很有用。

例如，当此设置激活时，关键词 'rose' 和 'Rose' 将根据输入被区别对待。

### 匹配完整单词

> 可以在条目级别覆盖。

仅包含一个单词的关键词条目只有在搜索文本中存在整个单词时才会被匹配。默认启用。

例如，如果启用了此设置且条目关键词为“king”，那么诸如“long live the king”的文本会被匹配，但“it's not to my liking”则不会。

**重要：** 当与不使用空白字符分隔单词的语言（例如日语或中文）一起使用时，此设置可能会产生不利影响。如果你用这些语言编写条目，建议将其关闭。

### 溢出时警告

如果已激活的世界信息超出分配的 token 预算，则显示警告。
