
# 数据银行（RAG）

检索增强生成（RAG）是一种为 LLM 提供外部知识来源的技术。它通过访问模型训练数据之外的信息，帮助提高 AI 回答的准确性。

SillyTavern 提供了一套工具，可以从多种来源构建多用途知识库，并在 LLM 提示词中使用收集到的数据。

## 访问数据银行

内置的聊天附件扩展（在 >= 1.12.0 的发布版本中默认包含）在“魔法棒”菜单中添加了一个新选项——数据银行。这是你管理 SillyTavern 中可用于 RAG 的文档的中心。

## 关于文档

数据银行存储文件附件，也称为文档。文档按可用范围分为三种。

1. 全局附件——在每个聊天中均可用，无论是单人还是群组。
2. 角色附件——仅在当前选择的角色中可用，包括他们在群组中回复时。_附件保存在本地，不会随角色卡导出！_
3. 聊天附件——仅在当前打开的聊天中可用。聊天中的每个角色都可以从中获取内容。

> **ℹ️ 注意**
>
> 虽然严格来说不属于数据银行的一部分，你甚至可以将文件附加到单条消息上。使用“魔法棒”菜单中的“附加文件”选项，或消息操作行中的回形针图标。


什么可以作为文档？几乎任何能以纯文本形式表示的内容都可以！

示例包括但不限于：

- 本地文件（书籍、科学论文等）
- 网页（维基百科、文章、新闻）
- 视频转录文本

各种扩展和插件也可以提供收集和处理数据的新方式，更多内容见下文。

## 数据来源

要将文档添加到任何范围，请点击“添加”并选择一种可用的来源。

### 记事本

从头创建文本文件，或编辑现有附件。

### 文件

从计算机硬盘上传文件。SillyTavern 为常见文件格式提供了内置转换器：

- PDF（仅文本）
- HTML
- Markdown
- ePUB
- TXT

你也可以附加任何非标准扩展名的文本文件，例如 JSON、YAML、源代码等。如果所选文件的类型没有已知的转换方式，且该文件无法作为纯文本文档解析，则文件上传将被拒绝，这意味着不允许上传原始二进制文件。

> **ℹ️ 注意**
>
> 导入 Microsoft Office（DOCX、PPTX、XLSX）和 LibreOffice 文档（ODT、ODP、ODS）需要安装并加载[服务器插件](https://github.com/SillyTavern/SillyTavern-Office-Parser)。请参阅该插件的 README 页面获取安装说明。


### 网页

通过 URL 抓取网页中的文本。然后使用 [Readability](https://github.com/mozilla/readability) 库处理 HTML 文档，仅提取可用的文本。

某些 Web 服务器可能会拒绝抓取请求、受 Cloudflare 保护，或严重依赖 JavaScript 才能运行。如果你在某个特定网站上遇到问题，请通过网页浏览器手动下载页面，并使用文件上传器附加。

### YouTube

通过视频 ID 或 URL 下载 YouTube 视频的转录文本，可以是创作者上传的，也可以是 Google 自动生成的。某些视频可能禁用了转录功能，此外，解析年龄限制视频也不可用，因为需要登录。

脚本以视频的默认语言加载。你也可以选择指定两个字母的语言代码，尝试以特定语言获取转录文本。此功能并非始终可用，可能会失败，请谨慎使用。

### 网络搜索

> **ℹ️ 注意**
>
> 此来源需要安装并正确配置[网络搜索](/extensions/websearch/)扩展。详情请参阅链接页面。


执行网络搜索并下载搜索结果页面的文本。这与网页来源类似，但完全自动化。所选搜索引擎将从扩展设置中继承，因此请提前设置好。

首先，指定搜索查询、要访问的最大链接数，以及输出类型：一个合并文件（按照扩展规则格式化）或每个页面一个单独文件。你也可以选择保存页面摘要。

### Fandom

> **ℹ️ 注意**
>
> 此来源需要安装并加载[服务器插件](https://github.com/SillyTavern/SillyTavern-Fandom-Scraper)。请参阅该插件的 README 页面获取安装说明。


通过 ID 或 URL 从 [Fandom](https://www.fandom.com/) wiki 抓取文章。由于某些 wiki 非常大，使用过滤正则表达式限制范围可能会有所帮助，它将针对文章标题进行测试。如果未提供过滤器，则所有页面都将被导出。你可以将每个页面保存为单独文件，也可以合并为单个文档。

### Bronie Parser 扩展（第三方）

> **⚠️ 注意**
>
> 此来源来自第三方，与 SillyTavern 团队**无关联**。此来源要求你安装 Bronya Rand 的 [Bronie Parser 扩展](https://github.com/Bronya-Rand/Bronie-Parser-Extension)，以及需要该解析器才能工作的服务器插件。


Bronya Rand 的 Bronie Parser 扩展允许将第三方抓取器（如 miHoYo/HoYoverse 的 [HoYoLab](https://wiki.hoyolab.com)）接入 SillyTavern，类似于其他数据来源。

目前，Bronya Rand 的 Bronie Parser 扩展支持以下内容：

- 通过 [HoYoWiki-Scraper-TS](https://github.com/Bronya-Rand/HoYoWiki-Scraper-TS) 支持 miHoYo/HoYoverse 的 HoYoLab（用于《原神》/《崩坏：星穹铁道》）

首先，按照[安装指南](https://github.com/Bronya-Rand/Bronie-Parser-Extension?tab=readme-ov-file#installation)安装 Bronya Rand 的 Bronie Parser 扩展，并将受支持的服务器插件安装到 SillyTavern 中。重启 SillyTavern 并进入_数据银行_菜单。点击 `+ 添加`，你应该会看到最近安装的抓取器已添加到可获取信息的来源列表中。

## 向量存储

现在，你已经为自己构建了一个关于特定主题的全面信息库。接下来呢？

要将文档用于 RAG，你需要使用一个兼容的扩展，将相关数据插入到 LLM 提示词中。

向量存储是 SillyTavern 自带的此类扩展的参考实现。它使用嵌入（也称为向量）来搜索与你正在进行的聊天相关的文档。

> **ℹ️ 有趣的事实**
>
>
> 1. 嵌入是数字数组，抽象地表示一段文本，由专门的语言模型生成。更相似的文本，其各自向量之间的距离更短。
> 2. 向量存储扩展使用 [Vectra](https://github.com/Stevenic/vectra) 库来跟踪文件嵌入。它们存储在用户数据目录 `/vectors` 文件夹中的 JSON 文件里。每个文档在内部由其自己的索引/集合文件表示。


由于向量功能默认处于禁用状态，你需要打开扩展面板（顶部栏上的“堆叠方块”图标），然后导航到“向量存储”部分，并在“文件向量化设置”下勾选“为文件启用”复选框。

向量存储本身不生成任何向量，你需要使用兼容的嵌入提供者。

## 向量提供者

> **⚠️ 警告**
>
> 嵌入只有在使用生成它们的同一模型进行检索时才可用。更换嵌入模型或来源时，需要重新计算向量。


### 本地

这些来源免费且无限制，使用你的 CPU/GPU 来计算嵌入。

1. 本地（Transformers）——在 Node 服务器上运行。SillyTavern 将自动从 HuggingFace 下载 ONNX 格式的兼容模型。默认模型：[jina-embeddings-v2-base-en](https://huggingface.co/Cohee/jina-embeddings-v2-base-en)。
2. WebLLM——需要安装扩展，以及[支持 WebGPU](https://caniuse.com/webgpu) 的网页浏览器。直接在浏览器中运行，可以使用硬件加速。自动从 HuggingFace 下载支持的模型。从此处安装扩展：<https://github.com/SillyTavern/Extension-WebLLM>。
3. Ollama——从 <https://ollama.com/> 获取。在 API 连接菜单中设置 API URL（在文本补全下，默认值：`http://localhost:11434`）。必须先下载兼容模型，然后在扩展设置中设置其名称。示例模型：[mxbai-embed-large](https://ollama.com/library/mxbai-embed-large)。可选地，勾选一个选项以将模型保留在内存中。
4. llama.cpp 服务器——从 [ggerganov/llama.cpp](https://github.com/ggerganov/llama.cpp) 获取，并使用 `--embedding` 标志运行服务器可执行文件。从 HuggingFace 加载兼容的 GGUF 嵌入模型，例如 [nomic-ai/nomic-embed-text-v1.5-GGUF](https://huggingface.co/nomic-ai/nomic-embed-text-v1.5-GGUF)。
5. vLLM——从 [vllm-project/vllm](https://github.com/vllm-project/vllm) 获取。首先在 API 连接菜单中设置 API URL 和 API 密钥。
6. Extras（已弃用）——在 [Extras API](https://github.com/SillyTavern/SillyTavern-extras) 下使用 SentenceTransformers 加载器运行。默认模型：[all-mpnet-base-v2](https://huggingface.co/sentence-transformers/all-mpnet-base-v2)。此来源不再维护，将来最终会被移除。

### API 来源

所有这些来源都需要相应服务的 API 密钥，并且通常有使用费用，但一般来说计算嵌入相当便宜。

## 向量化设置

在你选择了嵌入提供者之后，别忘了配置其他设置，这些设置将定义处理和检索文档的规则。

> **ℹ️ 注意**
>
> 附件的拆分、向量化和信息检索需要一些时间。虽然文件的初始摄取可能需要一段时间，但 RAG 搜索查询通常足够快，不会造成明显的延迟。


### 消息附件

这些设置控制直接附加到消息上的文件。

以下规则适用：

1. 只有适合 LLM 上下文窗口的消息才能检索其附件。
2. 当向量存储扩展被禁用时，文件附件及其附带的消息将完整插入提示词中。
3. 当文件向量化启用时，文件将被拆分为块，只有最相关的部分会被插入，从而节省上下文空间并让模型保持专注。

- 大小阈值（KB）——设置分块拆分阈值。只有大于指定大小的文件才会被拆分。
- 块大小（字符）——设置单个块的目标大小（以文本字符为单位，而非模型 token！）。
- 块重叠（%）——设置相邻块之间共享的块大小百分比。这允许块之间更平滑的过渡，但也可能引入一些冗余。
- 检索块数——设置要检索的最相关文件块的最大数量。它们将按原始顺序插入。

### 数据银行文件

这些设置控制数据银行文档的处理方式。

以下规则适用：

1. 当文件向量化被禁用时，不使用数据银行。
2. 否则，当前范围（见上文）中所有可用的文档都将被考虑用于查询。仅检索所有文件中最相关的块。同一文件的多个块按其原始顺序插入。
3. 插入的块将在适配聊天消息之前预留一部分上下文。

- 大小阈值（KB）——设置分块拆分阈值。只有大于指定大小的文件才会被拆分。
- 块大小（字符）——设置单个块的目标大小（以文本字符为单位，而非模型 token！）。
- 块重叠（%）——设置相邻块之间共享的块大小百分比。这允许块之间更平滑的过渡，但也可能引入一些冗余。
- 检索块数——设置要检索的文件块的最大数量。此额度在所有文件之间共享。
- 注入模板——定义检索到的信息将如何插入提示词中。你可以使用特殊的 \{\{text\}\} 宏来指定检索文本的位置，以及任何其他宏。
- 注入位置——设置插入提示词注入的位置。与作者注释和世界信息的规则相同。

### 共享设置

- 查询消息数——将使用多少条最新聊天消息来查询文档块。
- 分数阈值——调整以允许根据相关性分数（0——完全不匹配，1——完美匹配）剔除块的检索。较高的值允许更准确的检索，并防止完全随机的信息进入上下文。合理的值在 0.2（更宽松）到 0.5（更聚焦）之间。
- 块边界——一个自定义字符串，在将文件拆分为块时将优先使用。如果未指定，默认按（依次）双换行、单换行和单词间空格进行拆分。
- 仅在自定义边界分块——如果启用，分块将仅在指定的块边界处进行。否则，分块也将在默认边界处进行。
- 处理前将文件翻译为英文——如果启用，将使用聊天翻译扩展中配置的翻译 API 在处理文件之前将其翻译为英文。这在使用仅支持英文文本的嵌入模型时非常有用。
- 包含在世界信息扫描中——勾选是否希望注入的内容激活传说书条目。
- 全部向量化——强制摄取所有未处理文件的嵌入。
- 清除向量——清除文件嵌入，允许重新计算其向量。

> **ℹ️ 注意**
>
> 关于“聊天向量化”设置，请参阅[聊天向量化](/extensions/chat-vectorization/)。
