
# 群组聊天

## 回复顺序策略

决定群组聊天中角色回复的起草顺序。

### 手动

你可以从菜单中或通过 `/trigger` 命令手动选择要回复的角色。被选中的群组成员将是唯一回复的人。用户消息不会自动触发任何回复。使用空白用户输入触发生成将随机触发一个未静音的群组成员进行回复。

### 自然顺序

尝试模拟真实人类对话的流程。算法如下：

1. 从聊天中的最后一条消息中提取群组成员名称的提及。

    只有完整的单词会被识别为提及！如果你的角色名是 "Misaka Mikoto"，他们只会对 "Misaka" 或 "Mikoto" 触发，而不会对 "Misa"、"Railgun" 等触发。
    
    除非启用了 "允许自我回复" 设置，否则角色不会回复他们自己消息中对自己名称的提及！

2. 角色由 "健谈度" 因素激活。

    健谈度定义了角色在未被提及时发言的频率。在角色编辑器的 "高级定义" 屏幕中调整此值。滑块值在从 **0% / 羞涩**（角色除非被提及否则从不发言）到 **100% / 健谈**（角色总是回复）的线性范围内。新角色的默认值为 50% 几率。

3. 随机选择一个角色。

    如果在前面的步骤中没有角色被激活，则随机选择一个发言者，忽略所有其他条件。

### 列表顺序

角色根据其在群组成员列表中的显示顺序进行起草。不适用其他规则。

### 池化顺序

激活一个自从上一条用户消息以来尚未发言的随机角色。如果所有角色都已发言，则随机选择一个，直到下一条用户消息。

## 群组生成处理模式

此设置决定如何处理群组聊天成员的角色信息。无论选择如何，群组聊天历史始终在所有成员之间共享。

### 交换角色卡

默认模式。每次生成消息时，只有当前发言者的角色卡信息包含在上下文中。

### 合并角色卡

所有群组成员的信息按照列表顺序合并为一个联合提示。这有助于避免更改上下文大块内容的情况，例如在使用 llama.cpp 提示缓存时。

此模式有两个子模式（你必须选择其中一个）：

* 包含已静音 - 已静音的角色将始终包含在联合提示中。
* 排除已静音 - 如果已静音的角色不是当前发言者，则不会包含它们。

以下字段将被合并：

1. 描述
2. 场景（如果未对聊天进行覆盖）
3. 个性
4. 消息示例
5. 角色笔记 / 深度提示

**重要！** 请注意，由于典型角色卡的结构，使用此模式可能导致意外行为，包括但不限于：角色混淆自身、合并个性、不确定特质等。

### 合并前缀和后缀

当选择 '合并角色卡' 时，所有角色的相应字段将被合并在一起。这意味着在生成的提示中，所有角色描述将合并为一个大的文本块。如果你希望这些字段分开，你可以定义前缀和/或后缀。

这些选项支持普通宏，并将把 \{\{char\}\} 替换为相关角色的名称，把 \<FIELDNAME\> 替换为部分的名称（例如：description、personality、scenario 等）

## 其他群组聊天菜单选项

### 静音角色

群组聊天菜单中角色头像旁边的划掉的气泡图标可以禁用或启用聊天中特定角色的回复。

### 强制发言

群组聊天菜单中角色头像旁边的气泡图标将仅触发特定角色的回复，绕过回复顺序策略。即使群组成员被静音，此功能也会生效。

### 自动模式

当自动模式启用时，群组聊天将遵循回复顺序并触发消息生成，无需用户交互。当最后一个被起草的角色发送其消息后，经过 5 秒延迟会触发下一轮自动模式。当用户开始在发送消息文本区域中键入时，自动模式将被禁用，但已排队的生成不会自动停止。

### 允许自我回复

当选择了自然顺序时，如果每个回合的最新消息发送者因被自我提及而触发，则允许该角色连续回复。对列表顺序没有影响。

### 群组聊天场景覆盖

所有群组成员将使用输入的场景文本，而不是其角色卡中指定的内容。分支聊天从其父聊天继承场景覆盖，之后可以单独更改。

### 查看角色定义

单击群组聊天菜单中头像旁边的角色卡图标，将快速导航到通常的角色定义屏幕。此处所做的任何更改都将保存到角色卡本身。

要返回到群组聊天，请单击群组名称标题链接。

### 成员管理

你的任何现有角色都可以在群组聊天中添加、删除、静音或重新排序。默认情况下，新成员添加到群组成员列表的顶部，然后可以使用箭头图标重新排序。

### 群组聊天弹出窗口

可以通过单击 "当前成员" 字段旁边的图标激活群组聊天菜单弹出窗口。这将创建一个群组聊天菜单的弹出窗口。通过从用户设置中启用 MovingUI，此菜单可以调整大小并拖动到界面中的任何位置，其功能与常规群组聊天菜单相同。
