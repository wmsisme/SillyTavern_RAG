
# NovelAI

NovelAI 是一项付费订阅服务，可让您每月无限制地访问其高质量的自家文本生成、图像生成和文本转语音模型。在此处注册账户开始使用：<https://novelai.net/>

您将获得仅 *50次生成* 的免费额度来评估模型。当出现 **"Not eligible for this model"** 错误时，表示您的试用期已结束，需要订阅付费计划。

## 模型

如果您拥有 Opus，那么应使用 Erato 模型。如果没有 Opus，则 Kayra 是可用的最佳模型。

在 Tablet/Scroll 层级上，Clio 拥有更大的上下文大小，但 Kayra 的强度通常能弥补这一差异。

## 设置

包含设置的文件位于此处（`SillyTavern/data/<用户句柄>/NovelAI Settings`）。
您也可以手动添加自己的设置文件。

### 回复长度

每条消息您希望生成的文本量。注意 NovelAI 对每次回复有 150 个令牌的限制。

### 上下文大小

在任何给定时刻，上下文中保留的聊天令牌数量。可使用的最大上下文大小取决于您的模型和订阅层级：

- Kayra (Tablet) - 3072 个令牌
- Kayra (Scroll) - 6144 个令牌
- Erato (Opus 专属), Kayra (Opus) 以及 Clio (所有层级) - 8192 个令牌

### 序言

插入在聊天内容正上方的文本，用于修改写作风格。推荐格式是一组短标签，例如 "[ Style: chat, detailed, sensory ]"。

## 预设描述
根据 NovelAI 的说法，以下是默认预设适用的场景。

### Erato

* Golden Arrow - 良好的全能型预设。
* Wilder - 词汇选择更多样，重试时差异更大，更容易出错。
* Zany Scribe - 避免错误和重复。优先使用更复杂的词汇。
* Dragonfruit - 语言多变且复杂，重复少。错误和矛盾更频繁。
* Shosetsu - 专为日语写作设计。也适用于英语。

### Kayra

* Asper - 用于创意写作。期待意想不到的转折。
* Carefree - 良好的全能型预设。
* Fresh-Coffee - 保持内容方向。处理指令效果良好。
* Pro_Writer - 模仿畅销小说的节奏和感觉。
* Stelenes - 更倾向于选择合理的替代方案。重试时具有多样性。
* Tea_Time - 进入状态后效果很好。
* Writers-Daemon - 极具想象力，有时过于丰富。

### Clio

* Edgewise - 能很好地处理多种生成风格。
* Fresh Coffee - 保持内容方向。
* Long-Press - 适用于创意散文。
* Talker Chat - 专为聊天风格生成设计。
* Vingt-Un - 偏向散文风格的良好全能默认预设。

## 在 SillyTavern 中使用 NovelAI 的技巧和常见问题

从其他 ST 后端 API 切换到 NovelAI 时，会出现许多常见问题和疑问。差异归结于模型所训练的方向。您很可能使用过 OpenAI 或 Anthropic 模型（或仿造这些模型制作的本地模型），这些模型围绕遵循用户指令构建。NovelAI 的模型纯粹基于文本补全构建：NAI 的模型不是将您的输入作为消息并构思回复，而是尝试继续输入提示。由于这一差异，许多适用于其他 API 的技巧和常识对 NAI 并不适用。

### 为 NovelAI 调整设置

在高级格式设置（A 图标）下：
- 将"上下文模板"设置为"NovelAI"
- 将"分词器"设置为"最佳匹配"
- 勾选"始终将角色名添加到提示词"
- 勾选"折叠连续换行"
- 取消勾选"指令模式"下的"已启用"框

在用户设置（带齿轮的人物图标）下：
- 开启"滑动重试"（并非 NAI 专属，但非常有用，建议开启）

### 为 NovelAI 构建/适配角色卡

要优化角色卡以适应 NovelAI，推荐两种编写角色描述的方法：散文法和属性法。

散文法简单到让人觉得不可能有效："Sylpheed 是一个看起来年轻但实际上有 900 岁的森林仙女。她身材娇小，长长的白发在编成的侧马尾中渐变成绿色，眼睛是翠绿色十字形。[...]" 是的，就是这样。只需用正常句子写出角色的外貌、行为等，AI 就会理解。

如果您对自己的写作能力不够自信，或者希望采用更结构化的方式，可以使用属性法，这种方法存在于 NovelAI 的训练数据中。它作为不同类别角色特征的简单列表运作。以下是一些经过测试对 NovelAI 模型有效的属性列表：

```
Name:
AKA:
Type: character
Setting:
Nationality:
Species:
Gender:
Age:
Height:
Weight:
Appearance:
Clothing:
Attire:
Personality:
Mind:
Mental:
Likes:
Dislikes:
Sexuality:
Speech:
Voice:
Abilities:
Skills:
Quote:
Affiliation:
Occupation:
Reputation:
Secret:
Family:
Allies:
Enemies:
Background:
Description:
Attributes:
```

"Type: character" 是为了告诉 AI 这是在描述一个角色（区别于地点、物体或其他类型）。其余属性是可选的，有些是冗余的（例如 Personality、Mind 和 Mental 基本意思相同），但这些属性经过测试，与 NovelAI 的模型配合良好。填写与您的角色相关的属性即可。属性应使用小写书写，并用逗号分隔，单词无需加引号。例如：

```
Skills: lockpicking, stealth, running away very fast
```

推荐这些方法是因为它们存在于 NovelAI 的训练数据中，因此与模型配合得特别好。

#### 什么不该做

大多数现有的角色卡格式并不适合 NovelAI。它们可能会产生一些结果，甚至有些不错的结果，但存在很多问题。W++ 是最大的问题之一，它不像 NovelAI 模型训练时所使用的任何数据，并且它频繁使用括号/大括号/引号会消耗大量令牌，使卡片体积膨胀却没有实际好处。

在非 NovelAI 内置的现有格式中，AliChat 是最可能有效的，因为它依赖使用示例消息来同时传达角色信息和语气，并且采用 AI 应该输出的消息类型格式。

对于大多数其他格式，由于它们通常列出特定角色的不同特征，可以直接转换为属性法。

### 我应该使用哪个模块？

很可能不使用模块。如果您希望角色以更华丽的言辞说话，Prose Augmenter 很有用，但注意不要过度使用。Text Adventure 可能适用于文本冒险风格的卡片/故事。

### 不是使用指令模块吗？

您可以在需要时调用指令模块。在您的消息中创建一个新行，并用花括号括起您的指令，例如：`{ CharName is offended by that seemingly innocuous statement }`（文本和括号之间的空格是**必需的**）。这样做会临时自动将 AI 切换到指令模块一小段时间。您不希望一直使用指令模块，因为它往往比其他模块产生的创意输出少，只有在需要强力引导 AI 朝特定方向时使用。

### 为什么我的回复总是被截断？

NovelAI 将回复长度限制在约 150 个令牌，即使您将滑块调高也是如此。当达到滑块中的令牌数或 150（取较小值）时，它会额外生成最多 20 个令牌，寻找停止序列或句子结尾，因此回复的有效限制约为 170 个令牌，此时它会直接停止，导致截断。

如果被截断，您可以选择继续选项（在文本框左侧的三行菜单中），让角色继续回复。

如果您希望回复经常超过 170 个令牌，可以这样绕过限制：

- 将回复长度保持在 150 个令牌。
- 在高级格式设置中，启用自动继续。
- 将"目标长度"设置为所需长度。

这将把多次生成连接起来，以提供更长的消息，但如果模型决定停止，无法保证回复达到所需长度的 100%。

### 如何让机器人写出更长的回复？

阅读上文关于回复被截断的内容。这有助于确保回复不会因为达到生成长度限制而过早被截断。

如果您的回复没有被截断但仍然太短，很可能遇到了"垃圾进，垃圾出"的问题——如果您给模型提供糟糕的例子，它会产生糟糕的输出。如果角色卡没有示例对话或示例对话很短，并且您发送给机器人的消息也很短，模型就会理解并将其视为可接受的方式，从而导致回复变短。因此，编写更长的示例对话和更长的消息给机器人。（您也可以使用 NovelAI 为您编写一些示例对话，而不是自己动手。）

### 如何让机器人停止替我说话？

- 检查角色卡的第一条消息和示例对话是否包含角色替您执行操作的内容——如果有，则重新编写，去掉替您操作的部分。
- 确保"始终将角色名添加到提示词"已勾选。
- 确保您当前使用的用户身份与聊天中的其余部分一致。如果您更改了用户身份但没有改回来（或者没有将身份锁定到该聊天），则阻止为您生成的规则会失效。
- 在自定义停止字符串中添加 `["\n\{\{user\}\}:"]`（通常不需要，但有时会有所帮助）。

### 为什么我的角色没有回复？

很多原因可能导致这种情况，我们需要检查几个方面：

- 确保在高级格式设置中勾选了"始终将角色名添加到提示词"。
- 检查是否有来自 API 的错误。虽然您可以使用 SillyTavern 配合 NAI 免费试用版，但一旦试用结束，您只会收到错误。
- 检查您在"自定义停止字符串"中设置了什么——如果这些字符串在回复开头被生成，可能会导致提前截断。

### 我应该如何使用作者注释？

一般而言，您可能不应该使用。它被插入到上下文的末尾附近，而在 NAI 的模型中，它常常压倒上下文中的所有其他内容。它主要是早期较弱模型时代的遗留物，那时它更必要。

### 如何进行场景切换/时间跳跃？

将以下内容作为系统消息或在新行中放在您下一条消息的开头：
```
***
[ 2 days later ]
```

然后将消息的其余部分放在下一行。方括号中的文本可以是时间跳跃、新地点或其他任何内容。"***"（滑稽地被称为"分隔符"）告诉 AI 场景已切换，而括号中的文本则提供更多上下文。

### AI 不断重复特定的词汇/短语，该怎么办？

如上所述，您可以将重复惩罚滑块稍微调高一些，但调得过高可能会使输出变得语无伦次。
要更彻底地解决问题，请回溯整个上下文，特别是最近的消息，并删除重复的词汇/短语。将其从上下文中移除会降低 AI 一开始就说它的可能性。
